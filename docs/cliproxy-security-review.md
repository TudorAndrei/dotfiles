# CLIProxyAPI security review

Research date: 2026-10-15. This is a review of the checked-in setup and a read-only check of the running host. No server setting changed during this review.

## Current controls

The public Caddy site forwards `/llm/v1/*` and `/llm/backend-api/*` to the proxy on host loopback. Other `/llm/*` paths return 404. The dashboard uses Tailscale Serve on port 8445. CLIProxyAPI has a separate management key and `management.allow-remote: false`. The guest is an unprivileged Incus container. Its API and OAuth callback ports are forwarded to host loopback only. The guest config and management key have mode 600, and its OAuth directory has mode 700. See [Caddy config](../nix/hosts/nixos-laptop/media-public.nix), [deploy script](../scripts/cliproxy/deploy.sh), [bootstrap script](../scripts/cliproxy/bootstrap.sh), and [CLIProxyAPI management rules](https://help.router-for.me/management/apiv8).

## Ranked changes

1. **Limit dashboard access to named tailnet users or devices.** Tailscale Serve limits access to the tailnet, but it also follows the tailnet access policy. Tailscale's initial policy allows all devices to reach all other devices. Check the active policy, then use a grant for only the needed sources and `nixos-laptop:8445`. Do not rely on the management key as the only limit for every tailnet member. The host currently trusts `tailscale0` in its firewall config, so the tailnet policy is material here. [Serve](https://tailscale.com/docs/features/tailscale-serve), [default policy](https://tailscale.com/docs/reference/examples/acls), [grants](https://tailscale.com/docs/reference/syntax/grants), [host config](../nix/hosts/nixos-laptop/configuration.nix).

2. **Protect the management session in the browser.** Do not enable the dashboard's password-remember option. Its stored management key uses reversible obfuscation, and a same-origin plugin resource can read the stored session. Use a separate browser profile for the dashboard and install only trusted plugins. Rotate the management key if a browser profile or plugin is compromised. The management API can change config and OAuth files. [CLIProxyAPI Web UI](https://help.router-for.me/management/webui), [management API v8](https://help.router-for.me/management/apiv8).

3. **Review the public inference route and each client key.** Caddy currently forwards every path under `/llm/v1/*` and `/llm/backend-api/*`. Keep only the API paths that the clients use after a request trace confirms them. Use a different `access.api-keys` value for each device or person so a lost key can be removed without replacing every client key. Client keys are a list of accepted keys, not per-user policy or separate OAuth pools. If public access is no longer needed, move inference to Tailscale Serve too. [Caddy path matcher](https://caddyserver.com/docs/caddyfile/matchers), [CLIProxyAPI access config](https://help.router-for.me/configuration/options), [Caddy config](../nix/hosts/nixos-laptop/media-public.nix), [Serve](https://tailscale.com/docs/features/tailscale-serve).

4. **Pin and review the container image.** Compose uses `eceasy/cli-proxy-api:latest`, and each deployment pulls it. A tag can point to different image content later. Pin a reviewed image digest, record the version, and update it after review and a functional check. Keep a routine for security updates, because a pinned digest will not update by itself. [Compose file](../configs/cliproxy/compose.yaml), [Docker image digests](https://docs.docker.com/reference/cli/docker/image/pull/), [Docker build guidance](https://docs.docker.com/build/building/best-practices/).

5. **Reduce privileges inside the guest.** The Docker service uses host networking inside the Incus guest and runs with Docker's default capabilities. Test `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, a read-only root filesystem, and writable mounts only where the proxy needs them. Add each control only after the OAuth login, refresh, dashboard, and inference flows pass. Confirm that the Incus guest stays unprivileged; Incus requires `security.nesting=true` for Docker, but privileged Incus containers have greater host risk. [Compose service options](https://docs.docker.com/reference/compose-file/services/), [Docker capabilities](https://docs.docker.com/engine/containers/run/), [Incus security](https://linuxcontainers.org/incus/docs/main/explanation/security/), [Incus Docker setup](https://linuxcontainers.org/incus/docs/main/faq/).

6. **Tighten host access and secret files.** SSH currently listens on all host interfaces. The host disables password login, but the `tudor` user has passwordless sudo and full `incus-admin` access. Limit SSH to the needed network path and review who has the authorized private keys. Incus says `incus-admin` access is equivalent to trusted host root access. Some OAuth JSON files in the mode-700 directory have mode 644. Change new and existing credential files to mode 600 for defense if the directory permissions change later. Keep the config and key at mode 600. [Host config](../nix/hosts/nixos-laptop/configuration.nix), [Incus authorization](https://linuxcontainers.org/incus/docs/main/authorization/), [Incus security](https://linuxcontainers.org/incus/docs/main/explanation/security/).

7. **Bound request and log storage use.** The public route has no Caddy request-body size limit. Set a limit after measuring normal Codex and Claude Code requests; Caddy returns 413 when the limit is exceeded. The Compose service has no log-rotation setting. Docker's default `json-file` driver does not rotate logs, so choose its `local` driver or a bounded per-service log setting. [Caddy request body](https://caddyserver.com/docs/caddyfile/directives/request_body), [Docker logging](https://docs.docker.com/engine/logging/configure/), [Compose file](../configs/cliproxy/compose.yaml).

## Checks before a change

Check the active Tailscale grants, Serve status, NixOS firewall rules, Docker image digest, and CLIProxyAPI config on the host before applying a change. The repository does not prove that each live setting still matches it. After a change, test one allowed tailnet user, one denied tailnet user, public inference with a client key, public requests without a key, dashboard login, OAuth refresh, and the Caddy 404 path. Do not print keys or OAuth files in logs or test output.
