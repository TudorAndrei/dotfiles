# OpenCode Go with CLIProxyAPI

Checked 2026-10-16. This note is about the CLIProxyAPI service deployed on `nixos-laptop` by this repository. It does not show the live service state or a working OpenCode Go account.

## Findings

- OpenCode Go uses a subscription API key. OpenCode says to get the key in the Console, then select OpenCode Go in its `/connect` menu. The Go plan is $10 per month and Go Plus is $40 per month. A Go workspace can have one member. [OpenCode Go](https://opencode.ai/v2/docs/console/go/)
- OpenCode permits OpenCode Go use from other coding agents with similar traffic. It asks clients to send their own user agent and one stable `x-opencode-session` value per conversation. Its docs list Claude Code, Codex, and Pi as validated clients, but warn that some Codex and proxy setups omit the session header. A proxy must preserve it. [OpenCode Go, client rules](https://opencode.ai/v2/docs/console/go/#where-can-i-use-it)
- OpenCode publishes direct API endpoints for Go models. Models use different protocols: Responses, Chat Completions, Anthropic Messages, and Google. The current documentation uses paths under `/inference/go/...`. For example, `gpt-6-luna` uses `/inference/go/openai/v1/responses`, while `glm-5.3-flash` uses `/inference/go/openai/v1/chat/completions`. [OpenCode Go, endpoints](https://opencode.ai/v2/docs/console/go/#endpoints)
- A community [OpenCode Go CLIProxyAPI plugin](https://github.com/massiveits/opencode-go-cliproxyapi) routes these protocol families through one provider, discovers models, and accepts one or more Go API keys. It needs CLIProxyAPI v7.2.138 or newer. Its documented setup uses `plugins.configs.opencode-go-cliproxyapi.api-keys` and a compiled Linux plugin. This is a plugin from a separate author, not a native OpenCode Go login flag in CLIProxyAPI. [Plugin README](https://github.com/massiveits/opencode-go-cliproxyapi#readme)
- The plugin README still names `https://opencode.ai/zen/go/v1` as its default upstream URL. That differs from the current OpenCode endpoint paths above. Check the plugin against the current OpenCode API before deployment. Also check whether it forwards or supplies a stable session header. Its README does not state that behavior. [Plugin configuration](https://github.com/massiveits/opencode-go-cliproxyapi#configuration), [OpenCode endpoint and client rules](https://opencode.ai/v2/docs/console/go/)
- The repository's [Compose file](../configs/cliproxy/compose.yaml) mounts only the proxy config, OAuth files, and logs. It has no persistent plugin directory. Adding this plugin to the deployed Docker service would require a plugin mount and a compatible CLIProxyAPI image. The repository uses the moving `eceasy/cli-proxy-api:latest` tag, so the live version must be checked. [CLIProxyAPI Docker instructions](https://help.router-for.me/introduction/quick-start)
- Go limits are per model. The published five-hour allowance is 20% of that model's monthly limit, and the weekly allowance is 50%. OpenCode says limits and model lists can change. When a paid model reaches its limit, free models remain available. If the user enables **Use balance**, requests can use paid Zen balance after Go limits are reached. [OpenCode Go, usage limits](https://opencode.ai/v2/docs/console/go/#usage-limits)

## Practical path for this service

1. Get the Go API key in the OpenCode Console. Keep it in the guest's private configuration or secret store. Do not put it in this repository or print it in a command log. OpenCode Go requires an API key; the existing Codex and Claude OAuth logins do not add a Go account. [OpenCode Go](https://opencode.ai/v2/docs/console/go/), [plugin configuration](https://github.com/massiveits/opencode-go-cliproxyapi#configuration)
2. Check the live CLIProxyAPI version, the plugin ABI, the current upstream URLs, and session-header handling. The plugin needs a persistent mount in this repository's Docker deployment. [Plugin requirements](https://github.com/massiveits/opencode-go-cliproxyapi#requirements), [Compose file](../configs/cliproxy/compose.yaml)
3. After setup, request `/llm/v1/models` with the existing client key. Then make one small request with a Go model and confirm that it appears in OpenCode usage. The proxy's client key and the Go upstream key have different purposes. [Plugin model catalog](https://github.com/massiveits/opencode-go-cliproxyapi#features), [OpenCode Go usage](https://opencode.ai/v2/docs/console/go/#usage-limits)

No configuration was changed and no key was read for this research.
